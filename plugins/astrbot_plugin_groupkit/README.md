# 群助手（astrbot_plugin_groupkit）

AstrBot v4 插件 · 仅 OneBot v11（NapCat）
昵称体系（性别记号 / 群名片回改 / 强制改名） / 信息卡 / 额度与抽奖 / 签到 / 商店与名片皮肤 / 额度排行 / 发言统计 / 真实入群天数 / 表情图鉴 / 基础群管。

主打：**不用注册、口令是白话、菜单只列口令不写解释、不刷屏。**

三件事最能说明这个插件的性格：

- **昵称接管群名片，但只接管到「必要时」。** `🦊 李四` 这样的前缀由机器人拼，
  被人手动改掉会被掰回来 —— 但每条消息先做一次字符串比对，一致就零请求返回。
- **改名不收费。** 进来就要做的事不该收钱；要收钱用 `扣额度 @某人`，那是显式动作，
  会留痕。
- **菜单跟着权限走。** 1 级的人看不到「额度排行」，因为他不该看；关掉的功能整条消失，
  而不是留在菜单上点了报错。

另一条同样重要的取向：**这个插件基本不自己画图。**
好看的图交给会做图的人做（你），代码只负责三件事 —— 找到图、挑一张、
把字排到该在的位置上。所以「图放哪、怎么命名」是这个插件最重要的一份配置，
完整约定见 [`assets/images/README.md`](assets/images/README.md)。

| 目录 | 干什么 |
| --- | --- |
| `assets/images/checkin/` | 签到运势图。发「签到」时按种子抽一张，和文字一起发出去 |
| `assets/images/catalog/` | 表情图鉴。发「表情列表」时按文件名顺序发出去 |
| `assets/images/cards/` | 个人名片。`男.png`/`女.png` 是基础名片（按性别自动发），其余文件名就是商品名 |

丢一张图进文件夹立刻生效，不用改代码，也不用重启。

## 安装（Ubuntu 宿主机 / Docker）

### 1. 把插件目录放到 `data/plugins/`

解压后应该是这一层（`main.py` 必须直接躺在插件目录根下，不能多套一层）：

```
AstrBot/data/plugins/astrbot_plugin_groupkit/main.py
```

如果服务器上没有 `unzip`：

```bash
sudo apt update && sudo apt install -y unzip
unzip astrbot_plugin_groupkit.zip -d /path/to/AstrBot/data/plugins/
# 或者不装 unzip：
python3 -m zipfile -e astrbot_plugin_groupkit.zip /path/to/AstrBot/data/plugins/
```

**源码部署**：`data/plugins/` 就在 AstrBot 项目目录下，通常是 `~/AstrBot/data/plugins/`。

**Docker 部署**：

`data/plugins/` 是宿主机挂进容器的那个目录（compose 里 `volumes: - ./data:/AstrBot/data`）。
先确认映射关系：

```bash
docker ps --format '{{.Names}}\t{{.Image}}'
docker inspect <容器名> --format '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{"\n"}}{{end}}'
```

找到映射到 `/AstrBot/data` 的宿主机目录，把插件解压到它的 `plugins/` 下：

```bash
unzip /tmp/astrbot_plugin_groupkit.zip -d /path/to/data/plugins/
docker exec -it <容器名> ls /AstrBot/data/plugins/astrbot_plugin_groupkit
```

也可以用 `docker cp`（`/AstrBot/data` 是挂载卷，所以拷进去的文件同样持久）：

```bash
docker cp /tmp/astrbot_plugin_groupkit <容器名>:/AstrBot/data/plugins/
```

### 2. 装依赖（Pillow）

先检查镜像里是不是已经有，有就不用装：

```bash
docker exec -it <容器名> python -c "import PIL; print(PIL.__version__)"
```

缺的话：

```bash
docker exec -it <容器名> pip install Pillow
```

> ⚠️ **容器里 pip 装的东西在容器可写层，`docker compose down` 后重建会丢。**
> 插件文件放在 data 卷里不会丢，但 Pillow 会。永久化的做法是把依赖烧进镜像：

```dockerfile
# 在 docker-compose.yml 同目录建 Dockerfile
FROM soulter/astrbot:latest
RUN pip install Pillow
```

```yaml
# docker-compose.yml 里把 image 换成 build
services:
  astrbot:
    build: .
    # image: soulter/astrbot:latest   ← 注释掉这行
```

然后 `docker compose up -d --build`。以后重建容器 Pillow 都在。

### 3. 重载插件

AstrBot WebUI → 插件 → 找到「群助手」→ 点卡片上的刷新图标（重载插件）。

日志出现下面这行即成功：

```
[群助手] 已加载，数据目录：/.../data/plugin_data/astrbot_plugin_groupkit
```

### 4. 配置

插件配置里填 `enabled_group_ids`（**留空 = 机器人在的所有群都响应**，测试期建议先填目标群号）。

## 安装排错

| 日志 | 原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: No module named 'PIL'` | 没装 Pillow，或装到了别的 Python 里 | 用 AstrBot 那个解释器的 pip 重装 |
| `ModuleNotFoundError: ... core / utils` | 目录套多了一层，或缺文件 | 确认 `main.py` 和 `core/` 同级 |
| `Permission denied`（写 database） | 插件目录或 `plugin_data` 不可写 | `sudo chown -R $(whoami)` 对应目录 |
| 信息卡显示成纯文字 | 画图失败（字体读不到 / Pillow 没装） | 看日志里的「渲染信息卡失败」，插件会自动降级成文字卡 |
| 图鉴只出文字，没有图 | `assets/images/catalog/` 里没有图（或全是 `.psd` 这类不认的扩展名） | 丢几张 png/jpg 进去即可，不用重启；文字清单仍会列出全部模板名 |

验证结构：

```bash
find data/plugins/astrbot_plugin_groupkit -maxdepth 2 -type f | sort
```

应该能看到 `main.py`、`metadata.yaml`、`_conf_schema.json`、`requirements.txt`、
`core/`、`utils/`、`assets/`（字体 + 你自己的图）。

## 没有注册这一步

谁在群里说话，谁就自动有档案：

- **显示名**：`改名` 设置过的用它，否则用群名片（剥掉性别记号），最后才用 QQ 号。
- **性别**：先取 QQ 资料（`get_group_member_info` 的 `sex`）；没填就是「未设定」，
  用 `性别 女` 可以自己指定，指定之后不会再被协议端同步盖回去。
- **在册天数**：取**真实入群时间**（见下）。
- **新人礼**：第一次发言自动到账 10 额度，只发一次。

## 昵称体系

这一套做三件事：**管名字形状**、**管群名片长相**、**催新人把名字定下来**。
默认全开（`nick_enabled`）。关掉就退回老行为 —— 只存一个显示名，不碰群名片。

### 群名片长什么样

```
🦊 李四
↑  ↑
│  └── 名字：2~4 个字，不要数字，不要符号
└───── 性别记号：男 🦊 / 女 🐰 / 未设定 🧸
```

记号**只放群名片，不放名片图**。放图里等于把性别印在卡片上，改性别就要重画一次；
放群名片前缀则是纯文本，改一个字符立刻生效。

三个记号、分隔符、字数上下限、是否允许数字，全部可配。名字规则只有三条，
顺序就是新人最容易踩的顺序：

| 规则 | 默认 | 为什么 |
|---|---|---|
| 长度 | 2~4 字 | 一个字在群里没法称呼，五个字以上手机上一行就撑开了 |
| 数字 | 不允许 | 号码、年份、生日是「个人信息」，不是名字 |
| 符号 | 不允许 | emoji、标点、空格都算。`str.isalnum()` 对汉字字母为真、对标点 emoji 为假，正好是要的判定 |

### 改名 = 改群名片

`改名 李四` 一次做完三件事：写库 → 拼出 `🦊 李四` → 调 `set_group_card`。

**不扣额度。** 改名在这个群里是「进来就该做的事」，不是消费。新人没改名会被一直提醒
到被静音，这时候再收钱等于罚两次。要收钱由管理员发 `扣额度 @某人`，那是显式动作，
会进审计日志 —— 该留痕的收费不该藏在改名里。

群名片改失败（机器人不是管理员）会明确说出来，因为群友会去群里看名片，
不解释他会以为改名没生效。

### 头衔：买的是「一次修改权」，机器人提醒群主人肉去改

QQ 的群专属头衔**只有群主能设置别人** —— 机器人调接口改不动，这是 QQ 的
权限设计，绕不开。所以商店卖的头衔是一次修改机会，流程是：

```
购买 头衔（进背包，可囤）
  → 头衔 想要的字（限 12 字以内）
      → 扣一次机会，申请记录进佩戴位（签到文字、信息卡都显示）
      → 机器人 @ 群主：「群员 李四（QQ xxx）申请把群头衔改成：夜行者」
      → 提醒一次，交易完成 —— 群主改不改、什么时候改，是他的事
```

| 什么时候 | 发生什么 |
|---|---|
| `购买 头衔` | 背包 +1 次修改机会（可囤） |
| `头衔 想要的字` | 消耗一次，@ 群主请他去改（限 12 字以内） |
| `头衔 无` | 只清插件里的显示，**不**消耗机会（群头衔本身要请群主清） |
| `头衔`（不带参数） | 告诉你还剩几次机会 |
| `改名` | **不碰**群头衔 —— 改名和头衔互不相干 |

两个刻意这么定的地方：

- **找不到群主就不扣机会。** 「提醒」是这个交易里机器人唯一要交付的东西，
  交付不了（拿不到群成员列表）就不收钱，让人稍后再试。
- **只提醒一次，不建跟踪。** 群主忘记了是群主的问题，插件不去催第二遍 ——
  一个消耗品背后挂一套催办系统，复杂度远超它值。

为什么不把名字塞进头衔：名字已经在群名片里了（`🦊 李四`），头衔位置留着
正好放买的自定义头衔，两个字段各管各的。

### 群名片被手改，机器人会改回去

这是整套里唯一「主动改别人东西」的地方，所以做得很保守。

每条普通发言都会过一遍守卫，但守卫做的第一件事是**字符串比对**：拿
「机器人认为你的群名片该长什么样」和报文里带过来的真实名片比一次。一样就直接返回，
**零 API 调用**。只有真被人改掉的那一条消息才会发一次 `set_group_card`，
而且会回一句「（群名片帮你改回来了：🦊 李四）」—— 一天只说一次，
不说他会以为名片撞鬼了，每条都说就成了自己跟自己刷屏。

几个必须知道的细节：

- **名字合规就采纳，不合规才催。** 新人进群时群名片是 QQ 昵称，多半带符号，
  那就催他改；如果他本来就叫「小明」，一进群就合规 —— 直接采纳，不打扰。
  「用户自己已经做对了，就不该再要求他做一遍」。
- **改不动就放手。** 机器人不是管理员、接口报错、QQ 那头拒了，一律只记日志，
  绝不在群里喊「我改不了」。群友不该为机器人的权限问题买单。
- **剥记号要认三套。** 群主把 🦊 改成 🐯 之后，旧卡片里还是 🦊 开头。
  只认当前配置的话，所有老成员都会被解析成「名字叫『🦊 李四』」—— 带 emoji 的名字
  一律不合规，于是全群开始被催改名。所以内置的三个默认记号永远参与剥离。

### 强制改名：提醒 → 静音

`nick_force` 开着（默认）时，没登记名字的人会被推着走：

1. **入群时**在欢迎语后面追加一段改名提示（`nick_join_text` 可替换）；
2. **之后每次发言**都提醒一次，带着第几次 / 共几次；
3. 提醒够 `nick_nag_limit` 次（默认 3）还是没改 → 静音 `nick_nag_mute_minutes`
   分钟（默认 1），并把计数清零重新开始。

静音 1 分钟是刻意的：目的是打断他一下，不是惩罚。他去发一句 `改名 阿橘` 就自动恢复了。
计数在静音后清零（不管静音成没成）—— 失败了还每条消息都去调一次接口，
等于拿群消息打接口。

两段文案都可以自定义，`nick_join_text` / `nick_nag_text` 留空就用内置的。占位符：

| 占位符 | 含义 |
|---|---|
| `{name}` | 他现在叫什么 |
| `{min}` / `{max}` | 名字长度上下限 |
| `{rule}` | 一句话规则（「2~4 个字，不要数字，不要符号」），数字跟着配置走 |
| `{example}` | 一句示例，默认「阿橘」 |
| `{n}` / `{limit}` / `{mute}` | 第几次提醒 / 总共几次 / 静音几分钟 |

模板里有单个花括号（比如想写具体文字）不会抛异常，那一处原样发出去。

### 自由人：买了就不再管

商店里有个服务叫**自由人**（`freeman_price`，默认 500）。买了之后：

- 改名不再受字数、数字、符号限制（仍限 12 字 —— 那是排版上限，不是身份限制）；
- 守卫完全跳过他的群名片，随便改，机器人不掰回来。

这是「管」和「不管」之间留的一个出口。有人确实需要一个带符号的名字，
要么给他自由人，要么把整个昵称系统关掉 —— 后者是所有人的事，不该让一个人绑架全群。

### 关掉会怎样

`nick_enabled = false`：不写群名片、不加记号、不催改名，`改名` 走宽松校验（只限 12 字）。
信息卡、榜单、签到全都不受影响 —— 它们读的是库里的显示名，跟群名片没关系。

## 真实入群时间是怎么来的

两条来源，互为补充：

1. **协议端查询**：NapCat 的 `get_group_member_info` 会返回 `join_time`（unix 秒）。
   渲染信息卡时如果发现这个成员还没有 `join_time`，就查一次并缓存进库。
   所以**历史成员也能拿到真实入群时间**，不需要等通知事件。
2. **入群通知**：实时收到 `group_increase` 通知时直接记下时间戳，新成员立刻准确。

查不到（接口失败 / 协议端不返回）时才退化成「本插件第一次见到他的日期」。

在册天数 = 今天 − 入群日期 + 1，最少 1 天。

## 入群欢迎与入群验证

两件事、两个独立开关。默认：**欢迎开、验证关**。

- 欢迎默认开，是因为静悄悄进群体验很差 —— 一句「欢迎」+ 新人礼说明基本是零成本。
- 验证默认关，是它毕竟要拦真人的消息。被广告号骚扰过的群自己去开。

### 欢迎

有人进群时发一条，`{at}` 会真的 @ 到人（不是文字版 @，那个点不动）：

```
@小明 欢迎进来坐坐
新人礼 10 额度 已经挂账上了，发条消息就能领到。
不知道这里有什么，发「帮助」看一眼。
```

`welcome_text` 留空就是这个内置文案。想自己写可以用 `{at}` `{name}` `{group}`
`{quota}` `{currency}`，换行直接换行。模板里出现不认识的单花括号（比如想写
`{昵称}` 却拼错了）不会把整条搞丢，只是那一处原样发出去。

### 验证

开启后，新人进群的流程只有一条路，**全程在群里，不禁言、不走私聊**：

```
进群 → 验证题发群里 → 他在群里回答
     → 答对：放行；答错：吃掉不执行口令
     → 超时：移出群，并在群里说一句
```

三个刻意这么定的地方：

1. **不禁言、不发私聊。** 曾经做过「进群先禁言、题目走私聊」，实践下来是
   多此一举：私聊依赖 QQ 临时会话，对方关了就送不到；禁言又把群内答题这条路
   堵死（被禁言的人一条消息都发不出来）。现在定死为群里发题、群里作答，
   流程永远不会卡死任何人。
2. **超时是移出，不是继续关着。** 留在群里不出声的僵尸号比广告号更让人烦。
   移出用普通移出、不拉黑 —— 超时多半是人在忙，不该顺手断了他再申请的路。
3. **机器人不是管理员就只发提示、不验证。** 没权限时登记了也兜不住
   （踢不掉人），反而会把这个人的消息一直吃掉。

`verify_answers` 留空 = **发任意一条消息就通过**（挡住机器人和广告号足够了）。
填了就只认这几个词，逗号分隔、不区分大小写，答错会提示正确答案。
答错的消息不会进命令分发、也不计入发言数 —— 不然「发一串答案蒙对」还能顺手刷
抽奖进度。

验证期间待验证的人发消息会被拦下：不执行口令、不计数、不触发 AI 回复。

## 口令

口令**不需要任何前缀**，直接说话即可。

### 所有人（1 级）

| 口令 | 说明 |
|---|---|
| `签到` | 每日签到领额度：**一段文字 + 一张运势图**，图和字在同一条消息里 |
| `签到记录` | 最近 10 天明细 + 距下一个里程碑还差几天 |
| `签到排行` / `签到排行 累计` | 群内连签榜 / 累计榜 |
| `背包` | 头衔 / 关系 / 抽奖次数都在这里，空的时候回「空空如也~」 |
| `头衔 夜行者` | 消耗一次修改机会，@ 群主请他去改群头衔；`头衔 无` 只摘插件显示（不耗机会） |
| `关系 挚友 @某人` | 结缔关系：机器人 @ 对方征询，同意才生效；拒绝 / 超时资格退回背包 |
| `关系 解除` | 解除现在的关系 |
| `商店` | 货架：服务 / 头衔 / 关系 / 名片皮肤 / 消耗品（**合并转发**，防刷屏） |
| `购买 双倍卡` / `购买 抽奖券` / `购买 夜行者` / `购买 樱花` / `购买 自由人` | 下单，扣费在事务里完成；头衔和关系**进背包**，名片买完自动换上 |
| `查` | 个人信息卡（图）：姓名 / 性别 / 爱好 / 额度 / 注册天数 / 关系 |
| `查 @某人` / `查 123456789` | 看别人的信息卡，QQ 号不必在这个群里 |
| `名片` | 现在用的名片 + 全部皮肤 + 已拥有哪些 |
| `换名片 樱花` / `换名片 默认` | 换一张已买过的名片 / 摘掉 |
| `改名 李四` | 改显示名**并改群名片**（`🦊 李四`），不扣额度 |
| `性别 女` | 指定性别，决定群名片前面的记号（男 🦊 / 女 🐰 / 未设定 🧸） |
| `爱好 打游戏` | 设置爱好 |
| `额度` | 余额 + 抽奖进度 |
| `抽奖` | 消耗一次机会，随机 10~20 额度，回你「还剩几次」 |
| `今日` | 今日 / 本月 / 累计发言 |
| `额度记录` | 最近 20 笔额度变动（谁加的、什么时候，**合并转发**） |
| `给额度 @某人 50` | 转账：从自己账上扣 50，对方收 80%（进一），**所有人可用** |
| `发言排行` | 本群发言前十。默认关（`rank_message_enabled`），关着时这个口令完全失效，当成普通聊天，不解释原因 |
| `表情 摸头 @某人` | 做一张表情包，做成才扣额度；参数写 QQ 号也行。要写字直接跟在后面：`表情 举牌 你好 @某人`（不用引号） |
| `表情列表` | 发 `assets/images/catalog/` 里的图鉴图；多张打包成一条聊天记录 |
| `表情列表 3` | 只要第 3 张（想单存一张时用） |
| `表情详情 摸头` | 这个模板要几张图几段字 |
| `帮助` | 日常 + 娱乐**全部口令**，一条消息看全（长则合并转发） |
| `娱乐` | 只看表情包那一块 |
| `管理` | 只看群管那一块，按你的权限等级列出 |

### 2 级 · 助手

| 口令 | 说明 |
|---|---|
| `禁言 @某人` | 不写时长用配置的默认值（默认 10 分钟） |
| `禁言 @某人 1小时` | 写时长就按写的算，最长 30 天 |
| `解禁 @某人` | |
| `额度排行` | 本群余额前十，前三名用 🥇🥈🥉。**1 级看不到这个口令**，发了会回权限不足 |
| `改名 @某人 李四` | 代改他人显示名与群名片，不扣额度 |
| `性别 @某人 女` | 代改他人性别（连带群名片记号一起换） |

> 「额度排行」限 2 级，是因为它列的是全群余额。谁能看大家的家底，是群主该决定的事，
> 不该默认公开。要看的人自己 `授权 @某人 2` 就行。
>
> 「发言排行」相反，默认对所有人开（但总开关默认关）。发言数是公开行为，
> 没有隐私问题；关它只是因为人少的群看这个没意义。

### 3 级 · 管理

| 口令 | 说明 |
|---|---|
| `踢 @某人` | |
| `踢 @某人 拉黑` | 踢出去并拒绝再次入群申请 |
| `扣额度 @某人 50` | 不会扣成负数 |
| `授权 @某人 2` | 管理员只能设 1~2 级，也动不了 3 级以上的人 |

### 4 级 · 群主

| 口令 | 说明 |
|---|---|
| `全群禁言` / `全群解禁` | 封 / 解整个群 |
| `发额度 @某人 50` | 无中生有（印钱），可以发给自己；被授权到 4 级的人同权 |
| `授权 @某人 4` | 4 级可以设 1~4 任意级 |

### 权限怎么算

```
实际等级 = max(QQ 群角色映射, 插件内授权)
QQ 群主 → 4 级；QQ 管理员 → 3 级；普通成员 → 1 级
```

**授权分级受限**：管理员（3 级）只能设别人 1~2 级，也动不了现在已是
3 级以上的人；3~4 级要群主（4 级）来发。被授到 4 级的人拥有完整 4 级权限。

取 `max` 是为了防止手动授权把群主/管理员降权。这些规则**只写在管理台**
（数据页 → 成员 → 权限等级），群里不解释 —— 普通成员不需要关心管理分层。

## 签到与商店

一条 `签到` 出**一条消息**：一段文字 + 一张运势图（图和字是同一个消息里的两个部分，
不是两条独立消息 —— 后者在群里显得稀碎）。

```
🔥 今日签到 · 10月28日
==========================

芙熙 · 夜行者
「今天也来了」

✨ 大吉
宜 早睡 · 忌 赶末班车
幸运色 靛蓝 · 幸运数字 7

+24 额度 · 双倍卡已翻倍
连续 8 天 · 累计 41 天 · 余额 320

==========================
再签 16 天 · 额外 +100
                    [ 一张运势图 ]
```

为什么不画卡了（前三版都是 Pillow 画的）：代码画的卡永远比不上在本地用设计工具
做的那张，这一点群友一眼就能看出来；而签到是每天都会刷一次的图，底图固定会腻，
换成一组图轮着来才耐看。

运势图来自 `assets/images/checkin/`，**按种子挑**：

```
种子 = sha256("checkin-image|日期|群号|QQ号")
```

所以同一个人同一天重发「签到」，抽到的还是同一张 —— 否则群友会以为
「再签一次能换张好运势」，而奖励是用同一个种子算的，换了图不换奖励，
等于给了他一个错误的心智模型。

### 奖励怎么算

```
今日额度 = 基础(3~10) + 连签加成 + 里程碑加成   （买了双倍卡则整体 ×2）
连签加成 = min(连签天数-1, 10) × checkin_streak_bonus（默认 0）
里程碑    = 累计第 7/30/100/365 天额外 +20/+100/+300/+1000
```

连签加成默认是 0，签到收益就严格落在 3~10 里；里程碑仍然照发，那是长期目标
的奖励，不是每天的钱。

**基础额度不是真随机**，是 `sha256("checkin-base|日期|群号|QQ号")` 当种子取出来的。
同一天同一个人重算一百次都是同一个数。这么设计换来三件事：

1. 重发当天签到不用缓存奖励值，重算就行，数字不会变；
2. 机器人重启 / 热重载 / 改配置，已经发出去的文案照样对得上；
3. 群友问「为什么他 13 我 8」，能当场复现给他看。

连签只存「最后签到日期 + 当前连签」，断没断在签到那一刻现算。
不搞「每天定时清零」—— 机器人某天没在线，全群连签会集体作废。

运势（宜 / 忌 / 幸运色 / 幸运数字）用第三个种子 `fortune|日期|群号|QQ号`，
同样一天一人一份，理由一样：运势要是能重抽，签到就变成了抽卡。

### 商店卖什么

商店**不出图了**，纯文字货架，靠 emoji 分区 + `=` 分界 + 两列对齐；整包打成一个**合并转发**发出去 —— 货架越长越该收进一条聊天记录里，直接甩群里就是刷屏：

```
🛒 商店
==========================
余额 320 额度 · 累计签到 41 天

💳 服务
自由人  500 额度   改名不再受字数与符号限制，机器人也不再管你的群名片

🏆 头衔
头衔    100 额度   自定义群头衔的一次修改机会，想改什么自己定

💕 关系
挚友    200 额度   见过面聊过天的，才算朋友
铁子    200 额度   怎么闹都闹不散的那种
搭子    300 额度   饭搭子游戏搭子，干啥都有伴
情侣    520 额度   这个数字不用解释了吧

🪪 名片皮肤
樱花    50 额度    信息卡底图 · 樱花@50.png（正戴着）
夜空    80 额度    信息卡底图 · 夜空@80.png

🎲 消耗品
双倍卡  6 额度     下一次签到额度翻倍（今日已买 0/1）
抽奖券  15 额度    换一次抽奖机会（今日已买 0/5）

==========================
发「购买 名字」下单 · 买到的头衔和关系都进「背包」
```

| 商品 | 价格 | 逻辑 |
|---|---|---|
| 自由人 | 500 | **服务**，不是装饰：买完脱离昵称规则，一次性，不能重复买 |
| 头衔 | 100（`title_price`） | 卖的是「一次修改权」：进背包后 `头衔 想要的字` 消耗一次，内容自定义；可囤 |
| 关系（挚友/铁子 200，搭子 300，情侣 520） | — | 结缔资格：买进背包，`关系 名字 @某人` 发起，对方同意才生效；拒绝 / 超时退回背包 |
| 名片皮肤 | 文件名决定（默认 50） | 纯装饰，无限供给；买完自动换上 |
| 双倍卡 | 6 | 下次签到额度翻倍，立即生效，每日限购 1 |
| 抽奖券 | 自动（默认 15） | 换一次抽奖机会，次数显示在背包里 |

**「服务」和「商品」的区别。** 头衔、关系、名片、双倍卡都是**东西** —— 买完挂在你名下
（或背包里），看得见摸得着。自由人不是：它买完就把这个人从昵称规则里摘出去了。所以它单独一块、
排在第一位，也是货架上唯一「买完改变身份」的东西，以及新人第一个值得攒的目标。

**头衔和关系都进背包，不自动生效。** 买头衔买的是修改机会，改什么自己定；
买关系更慎重 —— 要等对方点头，所以资格先扣着，成了才花掉，不成退回来。

四个细节是刻意这么做的：

- **自由人 500 是有意的贵。** 它是「例外」的价格，不是功能的价格。定便宜了，
  所有人都会买，昵称规则就不再是规则了。500 大约是签到 50 次，或者攒一个月。
- **情侣卖 520 不卖 200。** 关系的价格里有一部分是仪式感，四个档位拉开，
  「结缔什么关系」本身就成了一个选择，而不是四个一模一样的图标。
- **双倍卡必须限购。** 它的价值就是「用额度换更多额度」，不限购等于印钞机。
  限一件，它就退化成一张每日优惠券，损失可控。卖 6 是因为一次签到平均拿 6.5，
  卖 6 买家才有点赚头，卖贵了没人买。
- **抽奖券的价格是算出来的，不是配的。** `(抽奖下限+上限)/2 + 暴击概率×暴击额度`，
  默认 `(10+20)/2 + 0 = 15`。卖贵了没人买，卖便宜了就是套利。
  管理员以后把 `draw_max` 调到 50，券价自动跟着涨，不会留下漏洞。

余额不足的那一次不会消耗当日限购名额（先验余额，再占名额）。

### 名片怎么上架

往 `assets/images/cards/` 丢一张图就行：

```
男.png            → 保留名，基础名片（不上架，按性别自动发）
女.png            → 同上
樱花.png          → 商品名「樱花」，卖 card_skin_price（默认 50）
夜空@80.png       → 商品名「夜空」，卖 80
星轨=200.png      → 同上，= 也认
```

价格只有一个来源：**文件名里的 `@价格`**，没写就用全局价。
没有第二个定价入口 —— 改价就是改文件名，两处都能写反而容易对不上。

`男` / `女` 是保留名，判的是整个文件名精确相等，所以 `男装.png` 照样是一件正常商品。
基础名片不在商店里出现，也不会被买走。

买完自动佩戴（买了不戴等于没买，群友还得再记一条口令），信息卡页脚会写一行
「名片 · 樱花」。基础名片不写 —— 每个人都在用，标出来只是噪音。

### 唯一还画图的地方：信息卡

整个插件只剩这一处会往上排字，而且只是**排字** —— 底图是你做好的成品：

- 底图 = 本人买的名片 → 按性别的基础名片（没写性别按男）→ 都没有就用程序画的浅色底；
- 版式固定 1280×720，字全在左侧：`姓名 / 性别 / 爱好 / 额度 / 注册天数 / 关系`
  —— 六行「标签 + 值」，模仿群主给的参考模板，值列对齐在一条线上；
- **不贴头像**。底图本身已经是一张人像，再贴一个圆头像就是一张图上两个人；
  而且头像要走一次网络下载，失败率不低，代价远大于收益。

字体走 `card_font_path`（默认自带 `assets/fonts/LXGWWenKai-Medium.ttf`，OFL 1.1），
找不到时自动回退系统中文字体，容器里一个中文字体都没有也不会变方块。

**画不出图会怎样**：渲染失败只影响这一次 —— 额度照发，只是发文字版。
信息不会丢，排版才会丢。

## 额度怎么来怎么去

- **来**：新人礼（默认 10）；每日签到（3~10）；每发言 100 条攒 1 次抽奖机会，
  `抽奖` 得 10~20。
- **去**：表情包（默认 3）、商店（头衔 100 / 关系 200~520 / 名片 50 / 自由人 500 / 双倍卡 6 / 抽奖券 15）。
- **改名不花钱**，用头衔、结关系也不另收费 —— 花掉的是买东西那一次的额度。
- 所有变动写 `quota_logs` 表，可审计；群友自己发 `额度记录` 就能看最近 20 笔（合并转发）。

签到 3~10 而抽奖 10~20，是有意的：签到是每天必做的小事，抽奖是攒够 100 条才一次的
小惊喜。前者给「稳定的少量」，后者给「不稳定的稍多」，两种节奏才不互相抵消。
连签加成与抽奖暴击默认都归零，就是为了让这两个区间严格成立 —— 想加惊喜可以去调它们，
但那时区间上限就不再是 10 / 20 了。

（上面括号里是配置默认值，以 `_conf_schema.json` 为准，别记成别处的数字。）

额度是为后续高阶功能（图卡、AI 对话、小游戏、骰子）预留的通用货币，
加新的消耗点只要调 `db.add_quota(..., -cost, "原因")`。

## 表情包

### 先搞清楚谁在画图

**这个插件不画图。** 画图的是 `meme-generator` —— 一个独立的服务，
插件只负责把「谁的头像 + 什么文字」发过去，把它画好的图转回群里。

这样分工的好处很实在：模板库有几百个模板、每个模板一堆素材图，
全部塞进插件会让插件变成几百 MB；而且模板要更新的时候，
重启一个容器就行，不用动插件代码。

### 起服务

两个版本都能用，插件启动时自动探测，你不需要配「我装的是哪个」。

**Python 版**（模板最全）

```bash
docker run -d \
  --name meme-generator \
  -p 172.17.0.1:2233:2233 \
  --restart always \
  -v /root/memeapi/memes:/data/memes \
  -e MEME_DIRS='["/data/memes"]' \
  meetwq/meme-generator:main
```

**Rust 版**（镜像小一个量级、启动快，自带两百多个模板，不用挂目录）

```bash
docker run -d \
  --name meme-generator \
  -p 172.17.0.1:2233:2233 \
  --restart always \
  meetwq/meme-generator-rs:main
```

两者的接口路径不一样，验证命令也不同：

```bash
curl http://172.17.0.1:2233/memes        # Python 版 → ["petpet", "kiss", ...]
curl http://172.17.0.1:2233/meme/keys    # Rust 版   → 模板 key 列表
```

**拿 Python 版的命令去测 Rust 版会得到 404**，这是路径不同，不是服务坏了。

模板库从这几个仓库拿（Python 版克隆到 `/root/memeapi/memes`）：

- `https://github.com/MemeCrafters/meme-generator-contrib`（官方扩展）
- `https://github.com/anyliew/meme_emoji`（表情包大户）
- `https://github.com/LRZ9712/tudou-meme`

一个模板一个目录，放进去重启容器就生效。

如果 AstrBot 本身跑在容器里，`127.0.0.1` 指的是容器自己，
要么把两个容器放同一个 network 用容器名访问，要么填宿主机内网 IP。

### 怎么用

```
表情 摸头 @小明
表情 举牌 你好 @小明
表情 摸头                ← 不 @ 就用你自己的头像
表情 摸头 #circle        ← 模板自定义选项，原样透传给服务端
```

素材来源按「你表达得有多明确」排序，位置也决定模板里的角色：

1. 引用消息里的图
2. 这条消息里带的图
3. 消息里贴的图片链接
4. 被 @ 的人的头像（按 @ 的顺序）
5. 还不够就补你自己的头像

所以「引用一张图 + 表情 摸头」和「表情 摸头 @某人」出来的效果不同 ——
前者用的是那张图，后者用的是那个人。

### 图鉴：发的是你自己做的图

**图鉴图不再由插件画。** 你自己做几张长图丢进 `assets/images/catalog/`，
`表情列表` 就按文件名顺序把它们发出去：

```
assets/images/catalog/
├── 01-热门.gif
├── 02-动物.jpg
└── 03-日常.png
```

文件名按**自然序**排（`2` 排在 `10` 前面，不是字典序）。想控制顺序就在前面
加编号，`01-`、`02-` 这样；想让群里看到的是「热门 / 动物 / 日常」，就把
`sogou` 那种内部 key 换成人话。

发送规则三条：

| 情况 | 行为 |
|---|---|
| 只有一张 | 直接发出来 |
| 多张 | **打成一条合并转发**，点开就是一整本，不刷屏 |
| `表情列表 2` | 只发第 2 张 —— 想单独存图的人用 |

页码超出范围会夹回最后一张，不会回一句「第 99/3 张」。

**为什么交给图片**：一张图能排字、能配图、能控制行距，比在聊天框里堆 400 个
模板名好看一个量级；而且你换一版图鉴，等于换一次皮肤，不用重装插件。

目录为空时退回文字清单 —— 群友要的是「都有什么」，不是一句报错。这时才用到
配置项 `meme_catalog_size`（一页多少个模板名），有图之后它就不起作用了。

改了图不用重启：目录的 mtime 变了就重扫，运行中丢一张进去立刻能发。

### 不做内容过滤

图鉴发的是你自己做的图，内容你排的版你说了算 —— 插件不介入，也没有
黑名单词表可配。兜底的文字清单同样原样列出服务端给的每一个模板。

需要控制尺度时去改图：`catalog/` 里放哪几张、图上排哪些模板，就是全部尺度。

### 扣费

**做成之后才扣。** 服务连不上、图下载失败、模板参数不对，一分不扣。
查模板列表、看详情、搜索都不扣。

同一个人 4 秒内只能做一张，这是防连点，不是防白嫖。

### 排错

| 现象 | 原因 |
|---|---|
| `连不上表情服务` | 容器没起，或 `meme_api_base_url` 填错。AstrBot 在 Docker 里时别填 `127.0.0.1` |
| `接口对不上` | 装的服务不是 meme-generator / meme-generator-rs，或者端口指到了别的东西 |
| `一个模板都没有` | Python 版没挂载 memes 目录；Rust 版正常自带模板，出现这句说明镜像没打全 |
| `没找到「xxx」` | 模板名不对，先发 `表情列表` 翻一遍 |
| 一直超时 | 动图模板很吃 CPU，调大 `meme_timeout`，或给容器多分核 |
| 做出来是空白图 | 模板缺素材文件，去容器日志看是哪个模板 |
| 容器日志里一路 404 | 用 Python 版的路径（`/memes`）测了 Rust 版，正常现象 |

## Web 管理台

AstrBot 的 WebUI 里会多出一个「群助手配置台」页面，不用在群里发口令就能改配置、换图、看数据。

入口：WebUI → 插件管理 → 群助手 → 页面上方的页面标签（AstrBot 4.16+ 才有这个能力）。

### 三个一级分区

这个页面存在的理由只有一个：**配置机器人**。所以配置是第一屏，数据和报表收到第三个分区里。

| 分区 | 是什么 |
|---|---|
| **配置** | 左边一列分组目录，右边只显示当前这一组。一屏 3~8 个字段，改完点底部保存条立即生效 |
| **素材** | 三个图片目录（签到运势 / 表情图鉴 / 名片皮肤）各几张、路径、含哪些文件；名片皮肤的价格表；命名规则 |
| **数据** | 左选群，右边五个二级页：群概览 / 成员 / 签到 / 额度 / 数据库 |

**为什么把素材单独立一个分区**：这个插件的图全部由你来提供，「放哪个文件夹、
文件叫什么」就是配置本身 —— 丢一张图进去等于上架一件商品。把它塞在配置项
里的某一行路径框中，等于让人猜。

### 配置页

分组来自 `core/settings.py` 的 `SECTIONS`，字段来自 `_conf_schema.json` —— 加一个
配置项只需要改这两个文件，页面不用动。目录右侧会显示每组「改了几项」，
底部保存条只在你改过东西时才出现。

三个值得一提的细节：

- **只提交改过的项**。整页覆盖会把别人同时在 WebUI 里改的值按旧值写回去。
- **改完立刻生效**，不用重启。保存时先在内存里改，再调一次 `save_config()` 落盘；
  落盘失败会**回滚内存**，不会出现「页面说已保存、重启后变回去」。
- 值域收敛是后端做的：填 9999 但上限是 365，会写 365 并在页面顶部说明为什么。
  页面上那行「实际生效」显示的是运行时真正在用的数字（上下限被拉平、0 表示不限购
  这类收敛都在这里体现），和「存了什么」是两件事。

### 数据页

| 二级页 | 看什么 |
|---|---|
| **群概览** | 六个全局数字（群 / 成员 / 今日发言 / 今日签到 / 额度总量 / 今日新增）+ 近 7 天发言柱状图（悬停看当天签到人数）+ 排行 |
| **成员** | 全群成员表，按显示名 / QQ 昵称 / 号码搜索，分页；每人一行额度、发言、连签、关系 |
| **签到** | 最近 40 条签到快照，和群友收到的那段签到文字读的是同一份数据 |
| **额度** | 最近 40 条额度流水，正负分色，能看到是谁操作的 |
| **数据库** | 库文件体积、结构版本、九张表各自的行数 |

排行有三个口径，面板右上角并排摆着 **连签 / 累计 / 额度**，亮着的那个就是当前口径。
前三名用 🥇🥈🥉，和群里的 `额度排行` 是同一套记号 —— 管理台和聊天里看到的名次
长得一样，人才不会怀疑两边说的不是一回事。

### 写操作一：调额度

成员表每行右侧的「调额度」。它走的是 `add_quota`，所以：

- 每一笔都会进 `quota_logs`，原因记为「管理台调整」，操作者记为 `web`，群里发 `额度记录` 能查到；
- 单次上限 100000，挡手滑多打一个零。

**为什么不给改连签天数 / 累计天数**：它们和 `checkin_records` 的快照是同一套账，单独改一处会让第二天的连签加成、里程碑进度全对不上。要补只有一条路 —— 让当事人发 `签到`。

### 版本不够怎么办

`register_web_api` 是 AstrBot 4.16 才有的。更老的版本上插件会记一条日志然后跳过管理台，**聊天功能完全不受影响**。不会因为一个网页把整个插件搭进去。

### 本地看版式

```bash
python tools/preview_console.py
# 生成 tools/out/console_{config_basic,config_card,assets,
#   data_overview,data_rank_quota,data_members,data_checkin,
#   data_quota,data_storage,empty,assets_empty}.html
# 里面塞了假数据和一个假宿主，直接用浏览器打开就能看，不需要 AstrBot
```

每张页面会自动切到对应的分区再截图，所以打开就是那一屏的样子，不用手点。

`console_empty.html` 是空库状态（新装插件、还没人在群里说过话），
`console_assets_empty.html` 是三个图目录都空着的样子 —— 新装的人第一眼看到的就是这两张，
空状态最容易写崩。

## 个人信息卡

信息卡是 **1280×720** 的浅色卡，也是这个插件**唯一还在绘图的地方** —— 而且只做一件事：
把你做好的底图拿来，在**左侧留白**里把字排上去。

底图按这个顺序找：

1. 本人买过并且正戴着的**名片**（`assets/images/cards/` 里那张商品图）；
2. **基础名片**：按性别选 `男.png` / `女.png`，没写性别按男；
3. 都没有 → 程序画的浅色渐变底（不会出不来卡）。

底图会 **cover 裁切**到 1280×720（不拉伸，人像不会变形）。不做模糊、不压暗 ——
底图是成品，糊一下只会把插画的线条和留白一起毁掉。

### 左侧那层白幕

底图是别人做的，谁也不知道左边到底白不白。所以渲染时会从左往右铺一层
由白到透明的渐变：纯白区铺上去看不出区别，满图的花底会被柔化成能读的浅底。
这比「要求底图必须留白」现实得多 —— 你只要记得**左边 600px 别放重要细节**。

### 卡上有什么

姓名之外固定五行，多一项都不放：

| 位置 | 内容 |
|---|---|
| 顶部 | `MEMBER CARD` + 一小段品牌色短线 |
| 姓名 | 最大的一行，一张卡只有一个视觉重心 |
| 五行 | 性别 / 爱好 / 额度（品牌色数字）/ 注册天数 / 关系，标签一列、值一列 |
| 页脚 | 右边「名片 · 樱花」（只标买来的） |

**为什么没有头像**：底图本身就是一张人像，再贴一个圆形头像就是一张图上两个人。
另外头像要走一次网络下载，失败率不低、还慢 —— 一个只为了「证明是本人」的小图，
代价是每次查卡都多一次可能超时的请求，不值。

**为什么没有发言统计**：那些数字长了会天天变，但没人会为了看它专门查一张卡；
真要看得去「今日发言」「额度记录」。卡上只放「会变、而且你会想知道」的东西：
额度够不够花、还有几次抽奖。

### 数字必须按基线对齐

额度 56px、抽奖次数 44px，字号不同。按 bbox 的**底边**对齐会因为两个字号的
descender 不一样而看出一条歪线 —— 这是最典型的「单个看都对、并排就歪」。
所以两个都用 `anchor="ls"`（left baseline），按基线摆。

同理，「128,000」到百万级会逐级缩字号（下限 30px），别让它压到右边那一栏。

### 怎么调

- 版式常量在 `utils/card.py` 顶部：`MARGIN` / `TEXT_RIGHT` / `LABEL_Y` / `NAME_Y` …
  纵向坐标是**写死**的：这是一张固定版式的卡，不是流式文档，拆成「上一个的高度 +
  间距」反而更难看出整张卡的呼吸是否均匀。
- 看当前效果：`python tools/selftest.py` → `tools/out/card_preview.png`。
- 想看**不同人 / 不同底图**的效果（没写性别、选了保密、超长名字、超长爱好、
  十二位额度、买了名片的、基础名片的）：`python tools/preview_cards.py`
  → `tools/out/card_*.png`。它会把真实的男女底图复制进临时素材目录，
  再补两张假商品图，走的是和管理台、商店完全同一条链路。

卡片是**每次调用现画**的：`domains/profile.py` 的 `card_reply()` 查库，
经 `services.py` 的 `card_data()` 组装成 dict，再交给 `CardRenderer.render(data)`。
同一个渲染器服务所有人，数据不同图就不同。

字体是霞鹜文楷（LXGW WenKai，OFL-1.1 授权），已随插件附带，也可换成任意 ttf。
大数字另外找 `arialbd` 之类的几何无衬线体 —— 数字要利落，中文要有温度，
一份字重做不到两件事；找不到就自动退回中文字体，不会崩。
QQ 名片里的 emoji 会被自动过滤（图片字体画不出来，会变豆腐块），名字过长会自动缩字号。

左列的小图标是**代码画的矢量图形**（人像 / 爱心 / 圆币 / 日历 / 时钟 / 柱状 / 星），
不用文字也不用 emoji —— 一是竖着读一列汉字容易读出别的词，二是 emoji 在图片里渲染不了。

## 数据层（为长期运行准备）

数据在 `data/plugin_data/astrbot_plugin_groupkit/groupkit.db`（符合 AstrBot 规范，
插件更新不覆盖）。单文件 SQLite，开启 WAL，读写不互堵。

### 表结构

| 表 | 主键 | 说明 | 增长量级 |
|---|---|---|---|
| `members` | `(group_id, user_id)` | 一人一行：显示名、性别、爱好、额度、累计发言、抽奖进度、权限、真实入群时间 | 群数 × 人数，有界 |
| `daily_stats` | `(group_id, user_id, stat_date)` | 一人一天一行，只用于算今日/本月 | 人数 × 天数，可裁剪 |
| `quota_logs` | 自增 `id` | 额度流水，只增不改，可审计 | 可裁剪 |
| `op_logs` | 自增 `id` | 群管操作审计（禁言/踢人/授权…） | 可裁剪 |
| `checkins` | `(group_id, user_id)` | 签到状态：当前连签、累计、最长连签、最后签到日、挂着的头衔（自定义原文）、双倍卡标记 | 群数 × 人数，有界 |
| `checkin_records` | `(group_id, user_id, date_key)` | 签到快照，一天一条。签到文字里的奖励、运势、连签全部从这里读 | 人数 × 天数 |
| `bag` | `(group_id, user_id, kind, item_id)` | 背包：头衔 / 关系的消耗品计数 | 很小 |
| `member_skins` | `(group_id, user_id, skin)` | 已买过的名片皮肤。`skin` 取自图片文件名，图删了这条还在（图放回来照样能戴）；当前戴哪张存在 `members.card_skin` | 很小 |
| `shop_purchases` | `(group_id, user_id, item_id, buy_date)` | 商店每日限购计数 | 人数 × 天数，一天后无用 |

- **累计发言数存在 `members.total_messages`**，不依赖明细表，所以裁剪 `daily_stats` 不会让累计数变少。
- **签到读的是快照不是实时状态**：重发当天的签到、改了配置、期间花掉额度，发出来的奖励数字和运势都还是第一次那份 —— 否则「重发一次换个吉凶」就成了玩法。
- **并发防重复签到靠 `checkin_records` 的主键**：同一人同一天第二条 `INSERT OR IGNORE` 的
  `rowcount` 为 0，立刻退出，不会重复发额度。进程内另有写锁，双击也串行。
- **日期一律按北京时间（UTC+8）算**，不看容器时区。Docker 默认 UTC，用 `date.today()`
  会让 0:00-8:00 的签到算成昨天。
- 时间字段统一：`join_time` 存 unix 秒（便于范围查询），`created_at` / `stat_date` 存
  `YYYY-MM-DD HH:MM:SS` / `YYYY-MM-DD`（人读友好，且字符串排序即时间排序）。

### 索引

按真实查询模式建，不做全表扫：

```
idx_daily_user_date      (group_id, user_id, stat_date)   今日/本月
idx_daily_group_date     (group_id, stat_date)            群维日报
idx_quota_user           (group_id, user_id, id)          按人查流水
idx_quota_time           (created_at)                     按时间裁剪
idx_op_time              (created_at)                     按时间裁剪
idx_members_quota        (group_id, quota DESC)           排行榜预留
idx_members_messages     (group_id, total_messages DESC)  排行榜预留
```

### 并发与一致性

- `isolation_level=None` + 显式 `BEGIN IMMEDIATE ... COMMIT`：所有多语句写操作（发新人礼、
  发言计数+抽奖结算、扣额度+记流水）都在一个事务里，**中途异常整体回滚**，
  不会出现「扣了钱没流水」或「加了机会没记账」。
- 进程内 `RLock` 串行化本插件的写操作；`busy_timeout=5000` 兜住跨进程冲突。
- **一个线程一条连接**。sqlite 连接不是线程安全的：A 线程正在 `fetch`，B 线程在
  同一连接上 `execute`，就会抛 `bad parameter or other API misuse`。管理台接口
  跑在 `asyncio.to_thread` 的线程池里，聊天路径跑在主循环，两边真的会同时碰库，
  所以连接按线程分开建；WAL 让读不挡写，写入仍由 `RLock` 串行。
- `synchronous=NORMAL` + WAL：在掉电风险和写入速度之间取均衡，是 SQLite 推荐的组合。
- 结构版本写进 `PRAGMA user_version`，配合「列是否存在」检查做可重复迁移，
  以后加字段直接往 `_migrate()` 里加一行，老库自动升级。

### 保留期清理

每天最多自动清一次（`_maybe_prune`），两个配置控制：

| 配置 | 默认 | 说明 |
|---|---|---|
| `log_retention_days` | 180 | 额度流水 + 操作日志保留天数，0 = 永久 |
| `stats_retention_days` | 730 | 按天发言统计保留天数，0 = 永久 |

裁剪只动明细，不动 `members` 上的累计值。

裁剪完会顺带跑一次 `PRAGMA optimize`（刷新索引统计，毫秒级）。
这里**刻意不做 `VACUUM`**：它会重写整个库文件、期间独占锁，放在热路径上
会卡住群消息。真要回收空间，是停机维护时手动做的事。

### 备份

`db.backup_to(path)` 是 SQLite 在线备份（不锁库），需要定时归档时直接调它。

## 加一个新功能

功能都在 `domains/` 里，`main.py` 不用改。以「表情包」为例：

**1. 建 `domains/sticker.py`**

```python
from ..core.command import Command, CommandEnv, HelpEntry, prefix

async def sticker(ctx, env: CommandEnv):
    # env.args 是口令后面的部分，env.event 可以发消息
    yield env.event.plain_result("🖼 表情包生成中…")

COMMANDS = [
    Command(
        key="sticker",                       # 唯一标识，重复会在启动时报错
        matcher=prefix(("表情包", "做表情")),   # 口令：表情包 xxx / 做表情 xxx
        handler=sticker,
        level=1,                             # 需要的权限等级；管理功能填 2~4
        perm_short="表情包",                  # 权限页里的简称
        help=(HelpEntry("表情包 文字", "生成一张表情包", page="base", order=60),),
    ),
]
```

**2. 在 `domains/registry.py` 的 `COMMANDS` 里加一行**

```python
from . import sticker
...
    *admin.COMMANDS,
    *sticker.COMMANDS,     # ← 放在哪个位置 = 匹配优先级，注意别被更宽的口令挡住
]
```

做完这两步，帮助菜单、权限页、权限校验全都自动生效。跑一遍
`python tools/selftest.py`，里面有断言盯着「管理命令有没有声明等级」
「帮助里的用法能不能真的命中命令」。

**要扣额度**：任何功能都走同一句，不要自己 UPDATE 余额表——

```python
ok, balance = ctx.db.add_quota(env.group_id, env.sender_id, -cost, "表情包", "system")
if not ok:
    yield env.event.plain_result(f"额度不够，这个要 {cost}")
    return
```

余额判断和扣减是同一条 SQL，并发下也扣不成负数。

## 本地自测

```bash
python tools/selftest.py
```

用桩替换 `astrbot.*`，跑 577 项断言，不启动 AstrBot、不连 QQ。覆盖的东西大致分四层：

| 层 | 盯的是什么 |
|---|---|
| 地基 | 口令解析（含「@ 的是 QQ 号」「昵称带空格」）、配置兜底与值域收敛、抽奖进度数学、事务回滚、索引齐全、保留期裁剪、在线备份、真实入群天数 |
| 业务 | 新人礼只发一次、余额不足拒绝扣款、并发扣不成负数、签到快照重发不变、运势与运势图同一天恒定、商店板块顺序与扣款、名片皮肤链（假图目录 → 商品名/价格/`@` 定价 → 默认图）、昵称体系（规则判定 / 记号拼装与剥离 / 守卫三次静音 / 自由人跳过 / 开关关闭后完全不动名片） |
| 输出 | 签到 / 商店 / 背包 / 排行的**文字版**排版（页头 emoji、分界线成对、中间空行保留、极端值不丢字段）、前三名奖牌、图鉴按张数分支 |
| 前端 | 配置台三个分区都在、`$("id")` 没有死引用、带 `hidden` 的元素不会被 `display` 盖住、前端没有外链也没有 fetch |

最后那一层值得单说：它拦的都是「截图看不出来」的错 —— 点了没反应、藏不住、
内网白屏。改版式之前先跑一次，比截十张图快。

昵称那一层尤其值得跑：守卫每条消息都会过，改错一个判断就会在群里连续作恶
（比如把所有人的名片都当成「不合规」开始刷屏催改名）—— 这种错在真群里发现
代价太大，在自测里发现只是几行红字。

改完代码先跑这个再传服务器。

## 已知待验证（第一次上线请确认）

1. **合并转发帮助**：`Comp.Nodes(nodes=[...])` 的参数名按当前文档写的，
   若日志报错，把 `help_style` 改成 `text` 即可回退，功能都在。
2. **`join_time` 字段**：NapCat 的 `get_group_member_info` 一般会返回。
   若某个版本没有，会自动退化成「插件首次见到他的日期」，不会报错。
   想确认的话看日志或临时打印 `get_group_member_info` 的返回。
3. **禁言时长**：QQ 侧上限 30 天，超出会被自动截断。
4. **`set_group_card`**：OneBot v11 标准接口，NapCat 都实现，但**需要机器人是
   群管理员**。改不动时不会报错给群里，只写一行日志，改名本身照常生效
   （库里的名字已经写进去了）。上线后如果群里名片一直没变，
   先看机器人是不是管理员。
   **群专属头衔插件碰都不碰** —— 它只有群主能设置别人，机器人调接口
   也是白调。「头衔」的流程是提醒群主人肉去改（见「头衔」一节）。

## 后续可以往上加（已留接口）

- **签到榜周榜 / 月榜**：`checkin_records` 一天一条，按日期区间聚合就有，
  只是在 `core/database.py` 加一个查询、`domains/rank.py` 加一个口令。
- **新的商店品类**：`core/checkin.py` 的 `ShopItem` 加一条，`_item_note` 给一句
  人话，`domains/shop.py` 的 `_rows` 会自动把它排进货架 —— 展示层不用动。
- **图鉴分群**：现在 `catalog/` 是全局一份。想给不同群不同图鉴，
  把 `images.pick_catalog(page)` 改成带上 `group_id`，目录按群号分即可。
- **接 AI**：写一个 `domains/ai.py`，用 `custom()` 匹配器做兜底口令
  （`return None` 表示不接），放在 `COMMANDS` 最后一位即可，前面所有命令
  都不命中时才会轮到它。
- **外部接口类功能**（热搜、票房、天气）：同样建 domain，注意这类要
  **先扣额度再请求**，因为烧的是你的额度；本地生成类建议**成功后扣**，
  做不出来不收钱。
