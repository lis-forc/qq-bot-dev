## 一、整条链路长什么样

```
QQ 客户端（你自己 / 群友）
        │  收发消息
        ▼
   QQ 账号（小号，NapCat 登录）
        │
        ▼
    NapCatQQ  ← 协议端：把 QQ 私有协议翻译成 OneBot 11
        │
        │  OneBot 11 over WebSocket（反向 WS：NapCat 主动连出去）
        │  ws://127.0.0.1:6199/ws
        ▼
    AstrBot  ← 框架：aiocqhttp 适配器（做 WS 服务端）
        │   把 OneBot 事件封装成 AstrMessageEvent
        ▼
   你的插件（data/plugins/<插件名>/main.py，class Xxx(Star)）
```

**关键点：插件写代码时，永远只面对 AstrBot 的 API，不直接碰 NapCat。**
只有在 AstrBot 封装不够用时，才穿透到底层，用 `event.bot.api.call_action("...")` 直接调 OneBot/NapCat 接口。

### 角色 / 端口速记

| 组件 | 角色 | 默认端口 | 说明 |
|---|---|---|---|
| NapCat WebUI | 配置面板 | 6099 | 日志里打印带 token 的 URL：`http://127.0.0.1:6099/webui?token=xxx` |
| NapCat 网络配置 | **WebSocket 客户端**（反向 WS） | — | URL 填 `ws://127.0.0.1:6199/ws` |
| AstrBot aiocqhttp | **反向 WS 服务端** | 6199 | 路径 `/ws`；Docker 部署时填 `ws://astrbot:6199/ws` |

连接成功的标志：AstrBot 日志出现 `aiocqhttp(OneBot v11) 适配器已连接。`
（现在你日志里能收到消息，说明这一段已经通了。）

## 二、NapCat 侧需要知道的（协议层）

### 2.1 四种网络配置类型（别搞混）

| 类型 | 谁发起连接 | 说明 |
|---|---|---|
| HTTP 服务端 | NapCat 收 | NapCat 当 API 被调用方 |
| HTTP 客户端 | NapCat 发 | 把事件 POST 出去（单工，只能收事件） |
| WebSocket 服务端（正向 WS） | 别人连 NapCat | 双工 |
| **WebSocket 客户端（反向 WS）** | **NapCat 连你** | **双工，AstrBot 场景用这个** |

### 2.2 OneBot 11 事件结构（插件里最终会变成 AstrMessageEvent）

所有事件公共字段：`time` / `post_type` / `self_id`。
`post_type` 取值：`message`（消息）、`message_sent`（自己发的）、`notice`（通知）、`request`（请求）、`meta_event`（心跳/生命周期）。

**消息事件**分 `message_type: private | group`：

- 私聊补充字段：`sub_type=friend`、`user_id`、`sender{nickname,sex,age}`
- 群聊补充字段：`group_id`、`sub_type=normal|anonymous|notice`、`sender{card,role}`（`role` = `owner/admin/member`）

**通知事件 `notice_type`** 常用：
`group_increase` / `group_decrease` / `group_ban` / `group_recall` / `friend_add` / `poke`（戳一戳）/ `group_upload` / `group_card` / `essence` / `lucky_king` / `honor`。
这些在 AstrBot 里**不一定**都封装成了标准消息事件 —— 要做“入群欢迎”“撤回监控”“戳一戳”这类功能，通常要读 `event.message_obj.raw_message`（原始 dict）判断，或者依赖 AstrBot 对应版本的支持情况。**这是后面要重点验证的一个点。**

**请求事件 `request_type`**：`friend`（加好友）、`group`（加群申请，`sub_type=add|invite`）。

### 2.3 消息段（Segment）类型 —— 消息链的基本单元

结构永远是 `{"type": "...", "data": {...}}`。

| type | data 关键字段 | 备注 |
|---|---|---|
| `text` | `text` | AstrBot 里对应 `Comp.Plain` |
| `at` | `qq`（`"all"` = @全体） | `Comp.At` |
| `reply` | `id` | `Comp.Reply` |
| `image` | `file` / `url` / `summary` / `file_size` | `Comp.Image` |
| `face` | `id` | QQ 表情，`Comp.Face` |
| `mface` | `emoji_id` / `emoji_package_id` / `key` / `summary` | 商城表情，接收时常转成 image |
| `record` | `file`（发时也支持 url/base64）、`path` | 语音，`Comp.Record`（AstrBot 只吃 wav） |
| `video` | `file` / `url` / `thumb` | `Comp.Video` |
| `file` | `file` / `name` / `file_id` | `Comp.File` |
| `json` | `data`（字符串或对象） | 卡片消息 |
| `music` | `type`(qq/163/kugou/kuwo/migu/custom) / `id` / `url` | 只能发，收会变 json |
| `forward` | `id`（发）、`content`（收，需 parseMultMsg） | 合并转发 |
| `node` / `nodes` | 节点 | 合并转发的组成，`Comp.Node(s)` |
| `poke` | `type` / `id` | 戳一戳，`Comp.Poke` |

> 配置项 `messagePostFormat: array|string` 决定上报是消息段数组还是 CQ 码字符串。AstrBot 建议 **array**（默认就是）。

## 三、AstrBot 插件侧 —— 真正的开发面

### 3.1 插件目录结构（放 `AstrBot/data/plugins/<插件名>/`）

```
astrbot_plugin_xxx/          # 推荐前缀 astrbot_plugin_，全小写、无空格、简短
├── main.py                  # 必须叫 main.py，插件类写这里
├── metadata.yaml            # 必须！AstrBot 靠它识别插件元数据
├── _conf_schema.json        # 可选：插件配置的 Schema，WebUI 自动生成表单
├── requirements.txt         # 可选：第三方依赖（pip 格式）
├── logo.png                 # 可选：市场 Logo，1:1，256x256
├── README.md
└── skills/                  # 可选：随插件提供的 Agent Skills
```

**metadata.yaml 关键字段**：`name` / `desc` / `version` / `author` / `repo`，另有可选 `display_name`、`short_desc`、`support_platforms`（如 `- aiocqhttp`）、`astrbot_version`（如 `">=4.16,<5"`，PEP 440 格式，不写 v 前缀）。

### 3.2 最小插件骨架

```python
from astrbot.api.event import filter, AstrMessageEvent, MessageEventResult
from astrbot.api.star import Context, Star
from astrbot.api import logger          # 用 AstrBot 的 logger，别用 logging

class MyPlugin(Star):
    def __init__(self, context: Context):
        super().__init__(context)

    @filter.command("helloworld")
    async def helloworld(self, event: AstrMessageEvent):
        """指令描述（会被 /help 解析，强烈建议写）"""
        yield event.plain_result(f"Hello, {event.get_sender_name()}!")

    async def terminate(self):
        """插件被停用/卸载时调用"""
```

硬性规则：
- 必须继承 `Star`；插件类**必须**在 `main.py` 里。
- handler 前两个参数固定 `self, event`；返回值用 `yield`（生成器）或 `await event.send(...)`。
- 一个插件类可以有任意多个 handler。

### 3.3 装饰器全家谱（`astrbot.api.event.filter`）

| 装饰器 | 作用 |
|---|---|
| `@filter.command("name")` | 注册指令 `/name` |
| `@filter.command("name", alias={"别名"})` | 指令别名（v3.4.28+） |
| `@filter.command_group("grp")` + `@grp.command("sub")` | 指令组（可无限嵌套，用 `@grp.group(...)`） |
| `@filter.event_message_type(EventMessageType.ALL/PRIVATE_MESSAGE/GROUP_MESSAGE)` | 按私聊/群聊过滤 |
| `@filter.platform_adapter_type(PlatformAdapterType.AIOCQHTTP \| ...)` | 按平台过滤（本机场景就是 `AIOCQHTTP`） |
| `@filter.permission_type(PermissionType.ADMIN)` | 仅管理员 |
| `@filter.on_astrbot_loaded()` | 钩子：框架加载完成 |
| `@filter.on_llm_request()` | 钩子：LLM 请求前，可改 `ProviderRequest`（`req.system_prompt`、`req.extra_user_content_parts`） |
| `@filter.on_waiting_llm_request()` | 钩子：等会话锁前，适合发“正在思考…” |

多个装饰器 = **AND** 逻辑。
**坑：事件钩子（on_*）不能和 command / event_message_type / platform_adapter_type / permission_type 混用。**
**坑：指令名不能带空格**，否则被解析成参数。

带参指令由框架自动解析类型：
```python
@filter.command("add")
async def add(self, event: AstrMessageEvent, a: int, b: int):   # /add 1 2 → 3
    yield event.plain_result(f"结果是: {a + b}")
```

### 3.4 事件对象 AstrMessageEvent

- `event.message_str` —— 纯文本内容（所有 Plain 拼起来）
- `event.message_obj` —— `AstrBotMessage`：`type` / `self_id` / `session_id` / `message_id` / `group_id` / `sender` / `message`(消息链) / `message_str` / `raw_message`(平台原始对象) / `timestamp`
- `event.get_sender_name()` / `get_sender_id()` / `get_group_id()` / `get_platform_name()` / `get_platform_id()`
- `event.unified_msg_origin`（UMO）—— 会话唯一标识，`平台ID:消息类型:会话ID`，**主动消息必须存它**
- `event.plain_result(text)` / `image_result(path|url)` / `chain_result([...])` / `make_result()`
- `event.send(...)` —— 只能在不能 yield 的场景（钩子 / 会话控制器内）用
- `event.stop_event()` —— 终止本事件后续处理（常用于阻止 LLM 再回复一遍）
- `event.is_stopped()` / `event.is_admin()` 等辅助方法存在，具体以本机版本源码为准
- `event.bot`（aiocqhttp 下）—— 底层 client，可 `await event.bot.api.call_action(...)`

### 3.5 发消息

**被动回复**（推荐，`yield`）：
```python
yield event.plain_result("Hello!")
yield event.image_result("https://example.com/a.jpg")   # 必须以 http/https 开头
```

**富媒体 / 组合消息链**：
```python
import astrbot.api.message_components as Comp
chain = [
    Comp.At(qq=event.get_sender_id()),
    Comp.Plain("来看这个图："),
    Comp.Image.fromURL("https://..."),
    Comp.Image.fromFileSystem("path/to/a.jpg"),
]
yield event.chain_result(chain)
```
组件：`Plain / At / Image / Record / Video / File / Face / Reply / Node / Nodes / Poke / Forward / Music`。
`Comp.File(file=..., name=...)`；`Comp.Record(file=wav路径, url=同路径)`（只吃 wav）；`Comp.Video.fromFileSystem/fromURL`。

**合并转发**（仅 OneBot v11 支持）：
```python
node = Comp.Node(uin=905617992, name="Soulter", content=[Comp.Plain("hi"), Comp.Image.fromFileSystem("t.jpg")])
yield event.chain_result([node])
```

**主动消息**（定时任务 / 延迟推送 / 别的会话）：
```python
umo = event.unified_msg_origin                     # 存起来
chain = MessageChain().message("Hello!").file_image("path/to/a.jpg")
await self.context.send_message(umo, chain)
```

> **坑（aiocqhttp 专属）**：发 `plain` 时框架会对文本做 `strip()`，前后空格/换行会被吃掉。需要保留就塞零宽空格 `\u200b`。

### 3.6 插件配置（`_conf_schema.json` → WebUI 表单）

放在插件目录，AstrBot 加载时生成 `data/config/<插件名>_config.json` 并**注入到 `__init__`**：

```python
from astrbot.api import AstrBotConfig

class ConfigPlugin(Star):
    def __init__(self, context: Context, config: AstrBotConfig):   # AstrBotConfig 继承 dict
        super().__init__(context)
        self.config = config
        # self.config.save_config()   # 需要落盘时
```

Schema 项字段：`type`（必填：`string/text/int/float/bool/object/list/dict/template_list/file`）、`description`、`hint`、`obvious_hint`、`default`、`items`（object 子 schema）、`invisible`、`secret`（敏感值遮罩）、`options` + `labels` + `subtitles`（下拉）、`slider{min,max,step}`、`editor_mode/editor_language/editor_theme`、`_special`（`select_provider` / `select_persona` / `select_knowledgebase` 等）。
版本更新时会递归补默认值、删多余项，**所以 Schema 可以放心演进**。

### 3.7 会话控制（多轮交互，比如“成语接龙”式流程）

```python
from astrbot.core.utils.session_waiter import session_waiter, SessionController

@session_waiter(timeout=60, record_history_chains=False)
async def waiter(controller: SessionController, event: AstrMessageEvent):
    text = event.message_str
    await event.send(event.plain_result("收到"))   # 这里不能 yield
    controller.keep(timeout=60, reset_timeout=True)  # 续期
    # controller.stop() 立即结束
    # controller.get_history_chains() 取历史消息链

await waiter(event)          # 超时会抛 TimeoutError
```
默认以 `sender_id` 为会话键；自定义 `SessionFilter.filter()` 可改成“整群一个会话”。
注意：会话控制器内**不能 yield**，只能用 `await event.send(...)`。

### 3.8 存储

- **KV（v4.9.2+）**：`await self.put_kv_data(k, v)` / `get_kv_data(k, default)` / `delete_kv_data(k)` —— 插件维度隔离。
- **大文件**：必须放 `data/plugin_data/<插件名>/`，**不要放插件自身目录**（重装/更新会被覆盖）。
  ```python
  from pathlib import Path
  from astrbot.core.utils.astrbot_path import get_astrbot_data_path
  p = Path(get_astrbot_data_path()) / "plugin_data" / self.name
  ```

### 3.9 穿透调 NapCat / OneBot 原生接口

```python
from astrbot.core.platform.sources.aiocqhttp.aiocqhttp_message_event import AiocqhttpMessageEvent

if event.get_platform_name() == "aiocqhttp":
    assert isinstance(event, AiocqhttpMessageEvent)
    client = event.bot
    ret = await client.api.call_action("delete_msg", message_id=event.message_obj.message_id)
```

拿平台实例（v4.0.0+ 写法）：
```python
from astrbot.core.platform.sources.aiocqhttp.aiocqhttp_platform_adapter import AiocqhttpAdapter
platform = self.context.get_platform_inst(event.get_platform_id())
assert isinstance(platform, AiocqhttpAdapter)
# platform.get_client().api.call_action(...)
```
（v4.0.0 之前是 `self.context.get_platform(filter.PlatformAdapterType.AIOCQHTTP)`，已废弃。）

常用 OneBot action：`send_private_msg` / `send_group_msg` / `delete_msg` / `get_msg` / `set_group_ban` / `set_group_kick` / `set_group_card` / `set_group_whole_ban` / `get_group_member_list` / `get_group_member_info` / `get_friend_list` / `get_group_list` / `send_group_forward_msg` / `set_msg_emoji_like` / `friend_poke` / `group_poke` …
NapCat API 文档：https://napcat.apifox.cn/

### 3.10 调试与发布

- 插件**运行时注入**，必须启动 AstrBot 本体才能调。
- 改完代码：WebUI → 插件页 → 卡片上的刷新图标（重载插件）；加载失败的在「加载失败插件」列表里点重载。
- 依赖：写 `requirements.txt`，别 import 了就完事。
- 规范：用 `ruff` 格式化；网络请求用 `aiohttp`/`httpx`，**不要 `requests`**（阻塞事件循环）；数据落 `data/`；做好 try/except，别让一个异常把插件打死。

## 四、内置指令与冲突（写插件前必看）

主程序自带：`/help` `/sid` `/name` `/reset` `/stop` `/new` `/stats` `/provider` `/dashboard_update` `/set` `/unset`。
更多管理类指令在 `builtin_commands_extension` 插件里：`/plugin` `/op` `/deop` `/model` `/history` `/ls` `/switch` `/rename` `/del` `/persona` `/llm`。

- **默认唤醒前缀是 `/`**，改了前缀则所有指令都要跟着改。
- `/sid` 是最好用的调试工具：能直接看到 UMO、UID、Bot ID、消息类型、Session ID —— 配管理员、配白名单、配路由都用它。
- 自己起指令名时**避开上面这些**，尤其是 `help` / `reset` / `new` / `stop`。

## 五、还没确认 / 要重点验证的点

1. **AstrBot 具体版本**（v3.x 还是 v4.x，v4 里 `get_platform_inst` 是新写法、`AstrBotConfig` 注入、`put_kv_data` 需要 4.9.2+）。版本不同 API 细节会变。
2. **notice 类事件（戳一戳、入群、撤回）在本版本 AstrBot 里到底以什么形式到达插件** —— 是标准事件、还是要读 `event.message_obj.raw_message`。
3. **指令 handler 执行完后是否会自动阻止 LLM 回复** —— 需要实测；保险做法是在 handler 末尾 `event.stop_event()`。
4. **群聊里指令是否需要 @机器人 才能触发**（取决于唤醒/前缀配置）。
5. 插件要实现的具体功能还没定 —— 等你的插件文件。
6. 插件开发/调试环境在哪：本机 Windows 是否装了 AstrBot 源码（能直接读源码就等于有最准的 API 参考）。
